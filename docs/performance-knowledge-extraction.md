# Performance knowledge extraction

The extractor turns one exact, human-reviewed evidence chain into a bounded
knowledge entry. It is an offline transformation, not an approval system,
benchmark runner or general-purpose recommendation engine.

## Inputs

- Original benchmark record JSON.
- Exact experiment plan JSON.
- External run submission JSON.
- Review packet regenerated by `review_performance_experiment_evidence.py`.
- Current append-only human decision ledger.
- Optional existing knowledge catalog.

## Example

```bash
python3 scripts/review_performance_experiment_evidence.py \
  --record record.json --plan plan.json --submission submission.json \
  --output review.json

python3 scripts/extract_performance_knowledge.py \
  --record record.json --plan plan.json --submission submission.json \
  --review review.json --ledger data/performance-review-ledger.json \
  --existing data/performance-knowledge.json \
  --output /tmp/performance-knowledge.updated.json
```

The decision must be the latest decision for the exact record, plan, experiment
and submission hashes, and must reference the regenerated review hash. Only
Supported and Refuted decisions are eligible. All six human attestations must
be true, the report must be unblocked, and the decision must cite valid runs
from both baseline and treatment. Inconclusive and Revision Required decisions
remain in the review ledger; they are not promoted to reusable knowledge.

## Knowledge contract

Each entry preserves:
- Human hypothesis and reviewer interpretation, without rewriting either as
  an independently proven causal law.
- Exact fixed context, intervention parameter and values, metric definition.
- Baseline/treatment medians, observed ranges, repetitions and threshold result.
- Reviewer, timestamp, limitations and applicability boundary.
- Exact evidence identity, review digest and cited run/source references.

The scope digest covers declared context, intervention and metric. If two
human-reviewed entries with the same topic and scope digest carry opposite
verdicts, the catalog records a potential contradiction for human resolution.
It does not pick a winner or silently overwrite older knowledge.

Knowledge IDs are content-derived for deduplication. The catalog is append-only
at the workflow level; create a new reviewed update rather than editing an old
entry in place. The hash values provide integrity references, not signatures or
proof of source authenticity. Source URLs and physical controls still require
human verification. The current implementation does not infer transferability
to other hardware, models, batch sizes, sequence lengths or software versions.
